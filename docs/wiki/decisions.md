## 2026-09-07 night: no Android phone (FACT, builder decision on the lead's recommendation)

The builder's Android phone is not available. Decision: do not buy one. Reasons: the official test wallet run and the presentation beat work on the iPhone (birthdate fallback for the iOS nested age quirk); the SP1 proof is server-side; the client-side Noir proof does not need a phone because the blind relay encrypts the wallet response to a key held by the user's device, and that device is the laptop for the submission (decrypt, prove in about 3.5 s, submit; the server never sees names). On-phone proving (WP5, Mopro) becomes an optional bonus, not a gate. WP5 is redefined as a desktop companion prover: consume the relay pickup, decrypt ECDH-ES A128GCM with the client key, run gen-prover and bb prove, submit through the bridge or directly via NoirPidVerifier.

- Main path is iPhone plus Mac (FACT, builder message 2026-09-08: the Android phone cannot be found; GPT review: no Android or on-phone requirement in the Uniswap prize or the judging criteria). - Issuer approval is enforced on chain (lead design, from the independent review in wiki/handoff-fable-2026-09-08.md). The registry keeps two facts per (subject, policyId): evidence (attestWithProof stores it, permissionless) and approval (a separate `approve` by an operator; attestByOperator implies approval). isEligible requires both, plus not revoked and not expired. Revoke clears approval; reapproval requires an operator. The proof path cannot reopen a revoked record. Bridge, app, scripts and tests follow (WP16). Rejected: delaying the UI only (does not establish the on-chain policy); auto-approval on proof (contradicts the product sentence in product.md).
- Privileged bridge operations (attest-operator, approve, revoke) require a bearer token; the verifier's bridge-mode result endpoint requires a shared token and returns no names by default (WP16, WP17). Rejected: unauthenticated issuer routes on a public origin.
- Work from the review is run as five parallel packages: WP16 issuer approval, WP17 service boundaries and trust contract, WP18 G0 runbook, WP19 evidence and submission repair, WP20 Attestat public copy and hosting preparation. Integration, merges and any deployment stay on the lead's main thread.
- Public surfaces say Attestat with attestat.dev as canonical URL; repository names, package and crate names, `nachweis:session:`, `nachweis.pid.over18.v1` and the `nachweis://handoff` scheme stay unchanged for this submission (accepted from the GPT review; recorded in name-and-domains.md as the rename scope).
